# KOSIS API 자동 확인

- KOSIS 대표 통계 43종을 기존 통계 공통 실행권·24시간 갱신·D1 발행 구조에 추가한다. 파일로만 제공하는 고령화연구패널조사는 원문 안내로 유지한다.
- 인증키는 기존 관리자 암호화 저장소에서 읽고 서버 안에서만 사용한다. 기존 KOSIS 키 읽기가 반환하는 percent-encoded 값을 다시 인코딩하지 않는다. upstream 오류 문구는 인증 URL을 포함할 수 있어 저장하지 않는다.
- 통계표설명 API의 PRD 수록주기를 확인한 뒤 통계자료 API의 `newEstPrdCnt=2`로 최신 두 수록시점을 조회한다. 기존 저장 기간은 유지한다. 월을 항목으로 제공하는 연간 표는 원자료 구조를 유지한다.
- 실제 PRD 메타데이터의 `년`과 자료 응답의 연간 코드 `A`, API 제목에서 생략된 쉼표·가운뎃점을 정규화한다. ITM 메타데이터에서 항목·분류 코드와 상위 분류를 확인해 필요한 코드만 요청한다. 단일 항목 설명과 가상분류는 값 분류와 구분한다.
- 최근 범위에서 과거 종료 항목이 빠지면 배포 확인본의 원래 시작연도부터 현재연도까지 재조회한다. 항목별 마지막 두 관측값을 검증·보관하고 기존 기간을 유지한다. 뒤 연도의 미수록 값은 null이며 이전 수치로 대체하지 않는다. 같은 이름의 상세/소계가 있는 두 표는 확인본의 소계 코드를 선택한다.
- API가 복합 단위만 제공하거나 단위를 생략한 항목은 공식표 확인본의 항목별 단위를 유지하며 `series.unit_source=verified_table`과 주석으로 명시한다. 다른 비어 있지 않은 단위가 돌아오면 반영하지 않는다.
- 기관·표·제목·항목·분류·단위·연도·누락·중복을 검증한다. 최초에는 공식 화면의 항목명을 완전히 대조하고, 이후에는 API 항목·분류 코드도 검증한다. 알 수 없는 분류를 생략해서 전체 값으로 만들지 않는다.
- 복수 표는 모두 검증한 뒤 함께 발행한다. 실행 시간 예산을 넘으면 검증된 임시 자료에서 이어 받는다. 실패하면 이전 정상 발행 자료를 보존하고 재시도한다.
- 주요통계의 국민기초생활보장 카드는 `kosis:basic-livelihood`로 교체한다. 2025년 확인본은 2,836,706명이며 지표누리 원본 `stat:2760`의 2,837천명은 별도 자료로 유지한다.
- 웹 초기 카드·선택 상세·주기적 조회·CSV·MCP가 같은 발행 자료를 읽는다. 관리자는 외부 연계 화면에서 각 표의 마지막 성공·다음 확인·오류·재확인을 볼 수 있다.
- 기존 돌봄자원 KOSIS 수요 자료의 공개 보류 및 장기요양기관 수집 설정은 이 기능과 독립적이다.

## 응답 지연 및 상태 표시 보강

- KOSIS의 각 조회 단계에 18초 응답 시간을 확보한다. 전체 실행 예산 22초·실행권 27초와 원천별 3초 간격은 유지하며, 남은 예산이 부족하면 저장된 메타데이터와 검증 부분에서 이어받는다. 정책 첫 적용 시 시간 초과 표만 한 번 재확인 대상으로 당기고 중간 자료와 정상 발행본을 보존한다.
- 중간 자료만 저장되어 있는 상태를 실행 중으로 간주하지 않는다. 유효한 실행권과 현재 작업 표가 일치할 때만 `checking`이며, 실패는 `retry_wait`, 중간 저장 대기는 `idle`과 `continuation_pending=true`로 구별한다.
- 시간 초과 오류에는 통계표 코드와 조회 단계(수록주기·항목/분류·최신값·과거값), 제한 시간만 남긴다. 인증키나 인증 URL, 원천 오류 원문은 기록하지 않는다.
- 일반 화면은 자료 기준 시점·표시 자료 확인일·최근 자동 확인 성공·다음 확인을 별도 표시한다. 관리자 화면은 최초 수집 진행 수, 최근 시도, 연속 실패 횟수, 한국어 실패 이유와 안전한 단계 진단을 제공한다. 요청이 없으면 다음 접속 시 재개한다는 실행 조건도 표시한다.
