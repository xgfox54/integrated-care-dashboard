## 반영 내용

1. 요청 제한 식별자에서 쿠키·User-Agent·언어 헤더를 제거했다. 신뢰할 수 있는 Cloudflare ingress IP를 정규화하고, 시간창별 식별자로 기존 IP 상한을 적용한다. X-Forwarded-For나 임의 인증 헤더로 식별자를 바꾸지 않는다.
2. 서버가 검증한 `verifiedSubject`를 전달할 수 있는 추가 계정 한도 접점을 마련했다. 이 값은 임의 헤더에서 가져오면 안 된다. **운영 OAuth 미들웨어 연결은 이번 공개 사본에서 수행하지 않았다.** IP 한도는 계정 한도와 독립적으로 유지된다. 공유망·AI 서비스 공용 egress의 정상 사용량은 운영 적용 전에 확인해야 한다.
3. `readBoundedBody`/`readBoundedJson`을 추가했다. 실제 청크의 UTF-8 바이트를 누적하고 초과 즉시 취소한다. 본문 수신 제한시간과 취소 신호를 적용하고, 초과 413·시간 초과 408·파싱 오류 400을 구분한다.
4. 웹 법령 API는 기존 64KiB 한도를 유지하되 스트리밍 단계에서 적용한다. MCP는 애플리케이션 본문 상한 256KiB, 배치 최대 20개를 적용하고, 검사된 JSON을 SDK의 `parsedBody`로 전달한다. 기존 SDK의 자체 보호를 대체해 없앤 것이 아니다.
5. URL 쿼리·JSON·중첩 객체·대소문자·인코딩 변형의 인증정보 마스킹을 보완했다. 기본 오류 로그는 허용된 오류 종류·요청 ID·경로·코드 중심이며 원문 예외 메시지와 스택을 저장하지 않는다. 로그 경로의 쿼리도 제거한다.
6. 법령 탐색과 실행이 하나의 불변 등록 목록을 사용하도록 변경했다. `setAllToolsRef` 전역 변경을 제거했다. 기존 직접 노출 법령 도구 10개와 웹 도구 8개는 유지하며, 내부 실행 가능 도구는 16개다.
7. 조례 검색/본문, 행정규칙 검색/본문, 조문 일괄 조회, 3단 비교, 신구 비교, 법령 일괄 검색의 전문 도구 8개를 명시적으로 등록했다. 원본의 모든 내부 도구를 공개하지 않는다.
8. 메타 도구 재귀·미등록 도구·잘못된 스키마·과대 params를 거절한다. 클라이언트 비밀값 및 prototype 특수 키를 제거하며, 웹/MCP 공통 실행 경로에서 공개 스키마와 원본 스키마를 재검증한다.

## 운영 Sites 적용 방법

운영 비공개 1.5.x 소스와 이 공개 사본은 동일하지 않다. 이 폴더 전체나 과거 `contract.ts`로 운영 소스를 교체하면 안 된다. 패치의 변경 부분만 최신 운영 소스에 병합한다.

1. 최신 운영 소스·미커밋 변경·배포 버전을 확인한다. 별도 작업 브랜치에서 `git apply --check remediation.patch`를 먼저 실행한다.
2. 검사 통과 시 패치 적용, 타입 검사, 전체 회귀시험, 빌드를 수행한다. 검사 실패 시 자동 덮어쓰기 없이 해당 부분만 수동 병합한다.
3. 운영 인증 미들웨어에서 안정적인 검증 주체 ID를 얻을 수 있을 때만 `verifiedSubject`를 연결한다. cookie나 Authorization 문자열을 인증된 주체 ID로 간주하지 않는다. 기존 OAuth·관리자·수집기 권한은 유지한다.
4. 최신 운영의 매뉴얼·통계·예산 도구와 D1, LAW_OC Secret, 수집기 설정을 보존한다. 비밀값 신규 발급이나 DB 재생성은 필요하지 않다.
5. 스테이징에서 인증·Origin·정상 법령 조회·조례 실행·공유 IP 제한·오류 응답을 확인한 뒤 기존 Sites 게시 절차로 배포한다. 로컬 커밋 또는 GitLab push를 Sites 배포 완료로 간주하지 않는다.
6. 배포 버전, 실제 소스 커밋, lockfile 해시, 시험 결과를 운영 기록으로 묶는다. 실패하면 코드 배포만 되돌리고 D1 데이터 공개본을 임의로 롤백하지 않는다.
