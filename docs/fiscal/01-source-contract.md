# 지방재정365 「세부사업별 세출현황」(QWGJK) 원천 계약

작성: 2026-10-04. 근거: 공식 주소에 표본키(Key 생략)로 직접 호출한 응답, 제3자 명세 수집본(heeseokuyang/lofin-api-mcp `_workspace/api_specs.json`)의 항목 목록. 비밀키 값은 이 문서·로그·화면에 넣지 않는다.

## 1. 인증·호출 (직접 확인)

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 주소 | `https://www.lofin365.go.kr/lf/hub/QWGJK` (HTTPS, GET) | 2026-10-04 호출 응답 200 |
| 인증 | 쿼리 `Key`. 생략하면 원천이 제공하는 표본키로 처리되어 페이지당 5건으로 고정 | pSize=100 요청에도 5건 반환 |
| 발급처 | 행정안전부 지방재정 개발자공간 lofin.mois.go.kr(본인인증 후 즉시 발급). 공공데이터포털 서비스키와 다름 | 제3자 안내, 미검증(키 미보유) |
| 형식 | `Type=json`, `pIndex`(1부터), `pSize`(명세상 최대 1,000, ERROR-336) | 표본키로 pIndex=2 정상 반환 확인 |
| robots.txt | `User-agent: * / Allow: /` | 직접 확인 |
| 이용조건 | 출처표시, 상업적·비상업적 이용 가능, 2차적 저작물 작성 가능 | 명세 수집본 meta.license(원천 화면 재확인 필요) |

## 2. 입력

| 필드 | 의미 | 상태 |
|---|---|---|
| `fyr` | 회계연도(필수) | 확인. 생략 시 ERROR-300 |
| `exe_ymd` | 집행일자 YYYYMMDD(필수) | 확인. 미래 날짜는 INFO-200 |
| `wa_laf_cd` | 지역코드(예 4900000 제주) | 확인 |
| `laf_cd` | 자치단체코드 | 4900000은 동작. 5013000은 INFO-200(코드 체계 미확인) |
| `dbiz_nm` | 세부사업명(부분일치로 보임) | 확인: 제주 「통합돌봄」 10건, 전국 579건(2026-10-01) |

부서·회계·분야로 거르는 입력은 명세에 없다. 이런 조건은 원천 범위를 모두 받은 뒤 저장소에서 적용하고 범위를 표시한다.

## 3. 출력 필드 (직접 확인)

응답 형태: `{"QWGJK":[{"head":[{"list_total_count":N},{"RESULT":{"CODE":"INFO-000"}}]},{"row":[...]}]}`.

| 원천 필드 | 의미 | 자료형(관측) | 내부 사용 |
|---|---|---|---|
| fyr, wa_laf_cd, wa_laf_hg_nm, laf_cd, laf_hg_nm, padm_laf_cd | 연도·지역·자치단체 | 문자열(앞자리 0 보존) | 재정주체 |

| dbiz_cd, dbiz_nm | 세부사업 코드·이름 | 문자열 | 재정사업 |
| exe_ymd | 집행일자 | 문자열 | 기준일(요청값을 그대로 돌려줌, 아래 6절) |

## 4. 레코드 단위

식별키: `fyr:laf_cd:acnt_dv_cd:dept_cd:dbiz_cd`. 한 수집에서 키가 겹치면 snapshot을 만들지 않는다(DUPLICATE_KEYS). 사업명+기준일을 키로 쓰지 않는다.

## 5. 완전성

첫 페이지의 list_total_count를 기준으로 페이지 수를 정하고, 페이지마다 총건수가 같은지, 끝까지 받은 고유키 수가 총건수와 같은지 검사한다. 하나라도 어긋나면 INCONSISTENT로 보류하고 마지막 공개본을 유지한다. 원천은 정렬 안정성을 따로 보장하지 않는다.

## 6. 시점

- 각 행의 exe_ymd는 요청한 날짜가 그대로 돌아온다(토요일 2026-10-03 요청에도 20261003). 그날 실제 갱신이 있었는지는 원천이 알려 주지 않으므로 snapshot에 그 사실을 적는다.
- 명세 설명: 지출액·집행잔액은 조회일 기준이며 출납폐쇄기간 이후 정리자료(1.1~1.20)는 12.31에 반영된다.
- 수집 기준일은 매일 10시(한국시간) 이후 전날이다. 실시간이라고 표시하지 않는다.

## 7. 오류 (직접 확인)

HTTP 200이어도 루트가 `{"RESULT":[{"CODE":...}]}`이면 오류다. ERROR-290(인증키), ERROR-300(필수값), INFO-200(자료 없음)을 직접 받았다. 명세상 ERROR-336(1,000건 초과), ERROR-337(일일 한도), ERROR-500/600/601(서버, 재시도 대상), INFO-300(키 사용 제한). 재시도는 서버 오류만 최대 3회이며 다음 날 새로 시도한다.

## 8. 금액 단위

정수 원 단위로 해석했다(예: 서울본청 「청렴문화 확산」 107,320,000). 이번 범위의 지방재정365 화면 대조는 하지 않았으므로 모든 관측에 `unit_verification=UNVERIFIED_IN_SCOPE`를 붙인다. 관리자가 표본을 화면과 대조한 뒤 범위를 승인한다.

## 9. 미검증·BLOCKED

- 발급 키로의 호출, 일일 한도, 1,000건 페이지: 키가 없어 미검증.
- 자치단체 전체 세출(사회복지·보건·부서별 모드): 표본키(5건/페이지)로는 제주본청만 5,710건(1,142회 호출)이라 수집하지 않음 → BLOCKED(발급 키 필요).
- 부서명: 원천에 없음. 서귀포시 통합돌봄과 부서코드 4005301은 작업지시서 대조기록 기준 후보 매핑으로만 둔다.
- 예산서(본예산·추경·결산)·부기명·산출근거: 원문 미수집(kordoc 경로 대기).
